diy Core Architecture Redesign

业务逻辑收拢到 core，验证器消除前端 if 判断

现状：业务逻辑散落三层，前端全是 if 判断
目标：四层分离，验证器消灭前端 if 判断

现状问题

  • • 前端散落大量 if — CLI/GUI/Socket 各写一套校验
  • • subject 校验 ×4 — 每个调用方自己查 state.yaml
  • • parent 校验 ×4 — create_task 内部也查一次（冗余）
  • • star_task 散落 ×4 — 本次 bug 根因
  • • 错误处理各异 — sys.exit / return str / QMessageBox
  • • 验证失败就 exit — 只能报第一个错误，用户得反复试

Validator 设计

  • • Schema 定义 — Pydantic BaseModel 或 dataclass
  • • validate() 收集全部错误 — 不短路，逐个 field 检查
  • • 返回 Valid() 或 ValidErrors([...]) — 不抛异常
  • • 每个 error 结构 — {field, code, msg} 三字段
  • • 前端通用展示 — 遍历 errors，打印/对话框展示
  • • 不依赖前端类型 — CLI/GUI 用同一套 error 结构

重构路径

  • • 1. 新建 core/ 模块 + core/validator.py
  • • 2. 定义 Schema + validate() 函数
  • • 3. Core 函数改为接收 ValidatedData — 校验过的数据
  • • 4. CLI 瘦身 — 删除所有 if/exit(1) → 调 Core 展示结果
  • • 5. Socket 瘦身 — 只协议解析 + 路由
  • • 6. GUI 瘦身 — 只收集输入 + 展示错误列表
